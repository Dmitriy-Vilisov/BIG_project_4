# Arbitrary Image Stylization: Real-Time Android App

Полноценное Android-приложение для переноса стиля на изображения и видеопоток с камеры в реальном времени прямо на устройстве, без использования серверов. Проект вдохновлен архитектурой приложения Prisma и использует нейросетевые модели формата TensorFlow Lite.


🌟 Ключевые особенности и кастомные доработки

    Плавная интерполяция стилей: Реализован механизм математического смешивания векторов стиля и контента. В файле StyleTransferHelper.kt интенсивность применения стиля вычисляется по формуле:
    blendedArray[i] = (styleArray[i] * styleWeight) + (contentArray[i] * (1.0f - styleWeight))
    Это позволило добавить в UI пользовательский ползунок для динамической регулировки силы эффекта в реальном времени.

    Использование Float-весов (FP16) для максимального качества: Вместо базовых, сильно квантованных (сжатых) INT8 моделей, которые дают артефакты, в ядро интегрированы полноценные Float-модели (MODEL_FLOAT = 1). Это значительно повысило художественную ценность генераций.

    Поддержка кастомных датасетов: В приложение зашиты пользовательские стили (включая отобранные картины из датасета WikiArt). Функция processInputImage автоматически центрирует, обрезает и сжимает любую нестандартную картинку до требуемого тензором размера (256x256), предотвращая вылеты приложения при работе с пользовательской галереей.


🧠 Архитектура ML-пайплайна

Пайплайн проекта был логически разделен на два этапа: исследовательский и Production.
1. Исследовательский этап (Local Training / Python)

Для понимания архитектуры Magenta и Arbitrary Style Transfer был поднят локальный пайплайн на TensorFlow 1.15.

    Данные (COCO и WikiArt) были конвертированы в формат TFRecord.

    Проведен тестовый запуск обучения графа (VGG-16 + Inception-v3) на CPU (всего 1000 шагов). GPU в теории можно использовать, однако TensorFlow 1.15 не знакома с современными видеокартами и с этим могут быть проблемы

    Результат: Успешное получение локального чекпоинта (model.ckpt-1000) и генерация тестовых интерполяционных сеток, демонстрирующих стадию underfitting'а нейросети на ранних этапах обучения.

2. Production этап (Android / Kotlin)

В мобильное приложение интегрированы официальные предобученные веса от Google. В основе лежат две нейросети:

    style_predict.tflite: Анализирует изображение стиля и извлекает из него вектор признаков.

    style_transfer.tflite: Принимает фото с камеры и вектор стиля, применяя стилизацию к контенту.


🛠 Проблемы и технические решения в процессе разработки

Проблема 1: Аппаратные ограничения и ошибки OOM при локальном обучении
При попытке обучить модель с нуля на домашнем железе, C++ ядро TensorFlow экстренно завершало процесс (Fatal Python error: Aborted и ResourceExhaustedError). Не хватало ОЗУ для инициализации тяжелого объединенного графа на датасете в 97 ГБ.

    Решение: Был применен подход Proof of Concept (локальное обучение на мини-выборке на 1000 итераций для доказательства владения технологией). Для финального мобильного приложения, следуя рекомендациям технического задания, были использованы официальные сжатые веса Google, что обеспечило стабильный инференс на смартфонах без перегрузки процессора.

Проблема 2: Вылет Android-приложения при инициализации моделей
Шаблон приложения падал с ошибкой размерности тензоров (размеры входных тензоров оставались равными нулю).

    Решение: Исходный код был написан под квантованные модели (style_predict_quantized_256.tflite). Логика StyleTransferHelper.kt была переписана: добавлена константа MODEL_FLOAT, а жестко заданные пути изменены на неквантованные style_predict.tflite и style_transfer.tflite.

Проблема 3: Слабое применение стиля на кастомных фото
В ходе тестирования выяснилось, что стиль накладывается слишком тускло, почти не перекрывая оригинальный контент.

    Решение: Перекалиброван механизм смешивания. Параметр styleWeight (отвечающий за интерполяцию) по умолчанию стоял на 0.5f. Настройки ползунка и базовые значения были смещены ближе к 1.0f, что дало яркий и акцентированный перенос стиля.

🚀 Установка и запуск

    Склонируйте репозиторий: git clone 

    Откройте папку проекта в Android Studio.

    Дождитесь синхронизации Gradle (убедитесь, что установлен Android SDK API 21 или выше).

    Убедитесь, что модели style_predict.tflite и style_transfer.tflite находятся в директории app/src/main/assets/.

    Соберите проект и запустите на физическом устройстве (рекомендуется для тестов камеры) или в эмуляторе.
